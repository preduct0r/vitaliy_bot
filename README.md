# Vitaliy Telegram Bot

Локальный Mac-бот для аудита и репетиции встречи. Это симулятор, не настоящий человек.

Установка: `uv sync --python 3.11 --extra dev`; на Mac нужны Poppler и LibreOffice для рендеринга.
Авторизация Codex остаётся на Mac. Токен и параметры хранятся вне Git в
`~/Library/Application Support/TOF Vitaly Bot/config.env`.

Для фактов TOF требуется настроенный внешний checkout `tof_v1` с SSH/Mutagen.
Укажите `VITALY_BOT_TOF_ROOT` — абсолютный путь к этому checkout (в окружении процесса).
Бот не содержит и не заменяет опубликованный ledger.

Запуск: `uv run python scripts/run_vitaly_bot.py`.
Проверка: `uv run pytest -q --tb=short`.
Полная инструкция: [docs/VITALY_TELEGRAM_BOT.md](docs/VITALY_TELEGRAM_BOT.md).

Частный операторский процесс S1 принимает JSON-список источников, подготовленную
карту только по обучающим встречам и независимо подготовленные темы holdout:

```
uv run --extra dev python scripts/hypotheses_private_corpus.py \
  --sources "$WORKFLOW_SOURCES" --training-map "$WORKFLOW_TRAINING_MAP" \
  --holdout-topics "$WORKFLOW_HOLDOUT_TOPICS" --corpus-version "$WORKFLOW_CORPUS_VERSION" \
  --output-dir "$WORKFLOW_OUTPUT_DIR/private-assessment"
```

Выходной каталог должен быть новым и находиться вне любого Git worktree. Все
принятые источники должны иметь абсолютный путь, дату ISO, вид `baseline` или
`transcript` и SHA-256. Записи со статусом `rejected` сохраняются в инвентаре,
но не в корпусе. Точное совпадение SHA выявляет только побайтовые дубли;
тождество разных версий одной встречи проверяется отдельно. Отчёт сохраняется
даже при отсутствии источника, неверном фрагменте или ошибке модели.

Текущая команда намеренно блокирует настоящий запуск модели: песочница
CodexRunner запрещает запись, но не подтверждает запрет чтения holdout-файлов.
Нужна проверенная изоляция файлов и отдельный независимый проверяющий. При
работающем боте запуск модели также запрещён. Детерминированные тесты с подменной
моделью проверяют механику, но не являются оценкой реального корпуса.

`SOURCE.json` фиксирует исходный commit TOF. Тег `baseline-before-point-corrections`
содержит версию до точечных исправлений. Откат кода не требует удаления новых
пользовательских данных; файлы состояния и резервные копии находятся вне Git.

Офлайн-пилот гипотез запускается только с подготовленными приватными индексом
корпуса и профилем S1. Перед генерацией он повторно проверяет фрагменты и хеши
источников, затем запрашивает покрытие текущего поколения через S2. Пример:

```
uv run --extra dev python scripts/hypotheses_pilot.py \
  --index "$WORKFLOW_INDEX" --profile "$WORKFLOW_PROFILE" \
  --verified-labels "$WORKFLOW_LABELS" --verifier-audit "$WORKFLOW_VERIFIER_AUDIT" \
  --private-verifier "$WORKFLOW_PRIVATE_VERIFIER" \
  --knowledge-version "$WORKFLOW_KNOWLEDGE_VERSION" \
  --coverage-request "$WORKFLOW_COVERAGE_REQUEST" --scope "насосы" \
  --output "$WORKFLOW_PILOT_OUTPUT"
```

Запрос покрытия — JSON контракта S2, например
`{"version":1,"scope":{},"period":{}}`. Выходной каталог должен быть новым и
располагаться вне checkout: в нём сохраняются карточки, снимок покрытия и отчёт
проверки источников и аудит проекции. Они могут содержать частные метаданные.
Генератор получает только канонические описания и идентификаторы проверенных
пар интереса и темы; оригиналы остаются приватными. Отдельный исполняемый
верификатор принимает JSON через stdin и возвращает JSON с `supported` и
`confidence`; отказ, ошибка или неопределённость блокируют результат.
Независимость проверяющего и полнота его проверки не гарантируются интерфейсом.
Числовое утверждение в отдельном текстовом поле допускается только при точном
совпадении всего поля с текущим запросом (без учёта регистра, пробелов и
завершающей точки). Вопросительный знак сохраняется. Это правило может отклонять
корректные перефразировки. Распознавание числительных ограничено и не является
универсальной гарантией; омонимы могут вызывать ложные срабатывания. Метаданные
покрытия не подтверждают числовые факты: числа из реестра пока намеренно не
поддерживаются. Офлайн-диагностика не является
holdout и не разрешает использование в production. Ошибка доступа к
серверу, неподтверждённые источники или отсутствие профиля блокируют пилот;
успех синтетических тестов не подтверждает проверку фактических источников.
В генерацию допускаются только интересы с проверенными свидетельствами из встреч
до 26 октября 2026 года. Ссылки карточек сопоставляются с конкретным интересом,
атрибуцией, датой и хешем источника; отчёт экспорта должен подтверждать те же
свидетельства и версии. Широта аналитических вопросов и фактическая применимость
маршрутов покрытия по-прежнему требуют отдельной проверки аналитиком.
