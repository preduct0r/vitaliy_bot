## Применение в боте

Активный профиль: `src/tof_reliability/vitaly_bot/data/vitaly_profile.v1.1.json`.
Прежний `vitaly_profile.v1.json` сохранён для сравнения и исторического holdout.
Изначальные десять встреч остаются в ядре, новые имеют отдельные ID
`2026-09-15-01` и `2026-09-15-02`. Вероятные записи и другой Виталий исключены.

Архивные паттерны и тайм-коды используются только как основания пакета знаний.
В новые пользовательские кейсы передаётся безопасная универсальная проекция
переговорного стиля, а не текст этих встреч или их бизнес-факты:

- Разложить полную сумму до выбранной базы и обосновать исключения (01, 12:07–14:44).
- Проверить сопоставимость дат и изменение состава данных (01, 18:01–20:42).
- Объяснить препятствие, мотивацию владельца и процедуру изменения (01, 00:00–03:32).
- Проверить физическую пригодность найденного ресурса (01, 21:24–24:22).
- Показать исполнение прошлых поручений и условие эскалации (02, 00:16–00:59; 11:28–12:12).
- Обосновать продолжение фазы с учётом ресурсов и альтернатив (02, 02:14–05:54).
- Выделить дополнительный эффект сверх уже получаемого бизнесом (02, 05:56–07:47).

Суммы, сроки, кадровые оценки и примеры из разговоров не переносятся в бот как
универсальные нормативы или подтверждённые факты. Упоминания гипотетической
экономии не дают основания обещать эффект. Пользу обновления ещё предстоит
измерить на новых встречах: добавление источников само по себе не является оценкой качества.

## Локальный архив новых встреч

Транскрипты, присланные через Telegram-команду `/meeting`, намеренно не
копируются в Git и не попадают в каталог выпуска. По умолчанию они находятся в
`~/Library/Application Support/TOF Vitaly Bot/knowledge/meetings/`; иной путь
задаёт локальная переменная `VITALY_BOT_KNOWLEDGE_DIR`. Рядом с исходником
сохраняются нормализованный текст, доступные рендеры и SQLite-индекс с хэшем,
датой, автором загрузки, атрибуцией Виталия и решением о дубле.

Другой локальный агент может только читать этот архив и его основания:

```zsh
sqlite3 -readonly "$HOME/Library/Application Support/TOF Vitaly Bot/vitaly_bot.sqlite3" \
  'SELECT id, meeting_date, title, status, source_path, normalized_path FROM meeting_submissions ORDER BY created_at DESC;'
```

Для просмотра того, почему запись повлияла или не повлияла на общий профиль,
используйте только read-only SQLite. Запрос ниже выводит метаданные и ссылки на
кандидат, но не сам текст транскрипта:

```zsh
sqlite3 -readonly "$HOME/Library/Application Support/TOF Vitaly Bot/vitaly_bot.sqlite3" '
  SELECT m.id, m.meeting_date, m.title, m.status, m.duplicate_of,
         m.continuation_of, m.learning_job_id, m.updated_at
  FROM meeting_submissions AS m ORDER BY m.created_at DESC;'
```

Новый путь архива задаётся только локальным `VITALY_BOT_KNOWLEDGE_DIR`; его
снимок попадает в приватный `knowledge.tar.gz` резервной копии, но никогда в
GitHub или каталог выпуска. Пакеты, кандидаты и причины решений хранятся в
SQLite; полные операторские запросы приведены в
[`docs/VITALY_TELEGRAM_BOT.md`](../../docs/VITALY_TELEGRAM_BOT.md).

Исходник является основанием, а не автоматически включённой памятью. В профиль
попадает только принятая запись после отдельного кандидата, независимой проверки
и выпуска нового пакета знаний. Старые удалённые файлы не реконструируются.
