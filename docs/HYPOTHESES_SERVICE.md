# Сервис гипотез: граница S4a

S4a добавляет сервисный API, но не добавляет команду Telegram, обработчики кнопок
или обучение в 04:00. Сервис не создаётся автоматически, не запускает poller и не
меняет конфигурацию действующего бота. Подключение выполняет следующий срез в
том же процессе и в существующем `FifoWorker` с тем же экземпляром runner.

`HypothesesService` получает `store`, `config`, общий `runner`, провайдер S2,
`knowledge_loader` и отдельный `TrustedRequestStore`. `submit` атомарно создаёт
`jobs` и `hypotheses_runs`; возвращённую задачу нужно передать существующему
воркеру через его `notify`. `get_run` требует владельца. Методы
`record_feedback`, `begin_feedback_input`, `submit_feedback_text` и
`cancel_feedback_input` работают с отдельными таблицами; обработка входящих
сообщений и кнопок должна вызывать их до обычной обработки материалов и не
отправлять текст отзыва в кейс или репетицию. У каждого события нужен
устойчивый `event_id`, а у каждого изменения — текущая `revision`. Повтор
того же события идемпотентен; другая команда со старой revision отклоняется.
Отзыв сохраняется для последующей проверки качества, но не публикует знания и
не создаёт кандидата текущего контура обучения.

`VerifiedKnowledgeLoader` требует явные частные каталоги, контрольную сумму
`audit-manifest.json` и точные `profile_version` и `knowledge_package_id` для
кейса. Он проверяет оригинальные пакеты классификатора и проверяющего по
инвентарю, сверяет все исходные трассы с ответами, заново воспроизводит
исходную проекцию и двойное разрешение конфликтов, проверяет ссылки и хеши
источников. Версия снимка привязывается к задаче при приёме; изменение до
выполнения блокирует её. Переданный существующий корпус является материалом
разработки: этот API не назначает его общим пакетом и не подтверждает
независимый holdout.

При генерации координаты частных фрагментов не передаются модели; допускается
только обобщённый контекст интересов и текущие проверенные материалы кейса.
Источники текущего кейса выбираются отдельно от серверных источников, проверяются
по хешам при постановке и выполнении, а выбранные ссылки сохраняются с
запечатанным результатом. Восстановление после прерывания перепроверяет текущее
поколение; при расхождении карточки не выдаются. Провайдер S2 в многоэтапном
пилоте выполняет одну попытку на обращение, чтобы сервис мог обеспечить один
общий повтор при изменении поколения. Отдельный `RemoteCoverageProvider.build`
сохраняет прежнее поведение с одним внутренним повтором.

Все пути для состояния, проверок и приватных источников должны быть вне Git.
Никакие эти API не являются разрешением на выпуск, запуск Telegram-тестов с
рабочим токеном или изменение production.
