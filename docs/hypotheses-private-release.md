# Частный выпуск знаний для гипотез

Функция по умолчанию выключена. Этот код и синтетические тесты не являются
подтверждением готовности реальной карты s1, её полноты или качества гипотез.
Новых независимых встреч для проверки не получено; исторические оценки не
пересчитываются, 70% не подтверждены. Управляющий процесс должен отдельно
сопоставить весь подтверждённый реестр встреч с фактической картой, файлами и
первичными трассами s1. Хеши обеспечивают контроль целостности относительно
доверенного SHA-256, но не являются электронной подписью и сами по себе не
доказывают ни авторство, ни полноту, ни корректность выводов модели.

## Формат частного пакета

Пакет, подготовленный оператором вне Git, состоит из `manifest.json` и файлов
JSON с простыми относительными именами. `format` равен
`hypotheses-knowledge-release.v1`, `purpose` — `production`, а
`developmental_only` — `false`. `version` — непустой идентификатор выпуска;
одно имя версии нельзя повторно использовать для другого содержимого.
`files` отображает каждое имя файла в его SHA-256. Роли `interest_map`,
`source_index`, `dimension_projection`, `classifier`, `verifier`,
`classifier_trace`, `verifier_trace` указывают на разные файлы из `files`.
`source_ids` должен совпадать с полным инвентарём `source_index.sources`;
версия карты и индекса равна версии выпуска. Каждая запись интереса ссылается
на источник из индекса. Карта должна соответствовать фактическому финальному
пакету s1, включая все подтверждённые поздние встречи, без подмены обучающей
картой до 26 октября. Локальные проверки не могут определить, какие встречи
оператор ошибочно не включил в оба списка.

Результаты классификатора и проверяющего находятся в `answer.candidates` и
`answer.verdicts`; каждая запись идентифицируется полями `interest_id`,
`source_id`, `dimension_id`, `locator` (два последних поля обязательны для
связи измерения). Наборы ключей должны совпадать без дублей. `supported` —
логическое значение, `confidence` — `high` или `low`. Каждое свидетельство
проекции требует отдельного положительного вердикта `high`, без
`conflicting`. Файлы трасс содержат разные `thread_id` и точные ответы в
`answer`. Оператор обязан независимо сверить эти экспортированные трассы с
оригинальными записями s1 и подтвердить происхождение; повторение ответа в
самостоятельно созданном файле не доказывает независимый вызов.

Для запуска генератора карта должна содержать `requirement` и `evidence` с
`source_id`, `locator`, `attribution`, а индекс — дату и SHA каждого источника.
Запуск дополнительно проверяет ограничения генератора и непустые связи
проекции. Записи встреч, частные фрагменты и иные закрытые поля не отправляются
в пользовательский интерфейс. Публичные формулировки и принадлежность фактов
должны быть проверены при приёмке управляющим процессом.

## Установка и отдельное включение

Оператор проверяет исходный манифест, получает его SHA-256 независимым от
содержимого канала и устанавливает выпуск в частный каталог вне Git:

```python
from tof_reliability.vitaly_bot.hypotheses_knowledge import VerifiedReleaseStore
store = VerifiedReleaseStore('/private/path/hypotheses-releases')
store.install('/private/path/verified-package', manifest_sha256='REPLACE_WITH_VERIFIED_SHA256')
```

Установка проверяет пакет до атомарного изменения указателя. Старый выпуск
остаётся доступным. В отдельной частной конфигурации вне Git задаются
`VITALY_BOT_HYPOTHESES_PRODUCTION=1`, абсолютный
`VITALY_BOT_HYPOTHESES_RELEASE_DIR` и доверенный
`VITALY_BOT_HYPOTHESES_RELEASE_SHA256`. Одновременное включение
`VITALY_BOT_HYPOTHESES_DEVELOPMENT=1` запрещено. Для переключения выпуска
нужно согласованно изменить указатель и доверенный SHA в отдельном выпуске
конфигурации при остановленном допуске новых задач; старые задания остаются
привязаны к прежней версии. `store.activate(version)` возвращает SHA старого
манифеста для согласованного отката. Изменение живой конфигурации и перезапуск
выполняет только управляющий процесс после проверки простоя и резервной копии.
Перед откатом к старому коду необходимо завершить или отдельно обработать
задания нового формата: старый код не умеет читать новые частные выпуски.
Новая колонка SQLite добавляется без удаления старых данных.

## Изменения интересов и обратная связь

Проверенные и опубликованные через существующий цикл общие правила анализа
снимаются при постановке нового задания, включая задания старого кейса; на
старые задания и закреплённый профиль кейса они не влияют. В промпт попадают
только шаблоны из разрешённого списка, а не исходный текст чужой реакции.
Это изменение правил анализа, а не автоматическая переработка карты интересов.
Принятая поздняя встреча может попасть в следующий выпуск только после
подготовки полного обновлённого индекса и карты, независимой классификации и
проверки, сверки с оригиналами и установки нового пакета; сбор этого пакета и
проверка полноты остаются обязанностью оператора. Автоматическое обучение по
одному отзыву или выдуманным результатам не заявляется.

Очередь процесса обеспечивает последовательность внутри процесса, но общего
межпроцессного mutex для независимых вызовов модели нет. До вызовов отдельной
модели и особенно до выпуска управляющий процесс должен проверить живую
очередь и процессы, не прерывая их. Нужны отдельный тестовый бот и актуальное
опубликованное поколение TOF; использовать production token для тестового
polling запрещено. При недоступном сервере приёмка не считается пройденной.
