# `tof_reliability.data` — доступ к ledger

Один загрузчик на таблицу ledger вместо `pd.read_csv` с угадыванием колонок.
Пакет отвечает на вопрос «как прочитать таблицу», а не «что она значит»: смысл
таблицы — в контракте `docs/contracts/<таблица>.md`, где что лежит — в
`DATA_MAP.md`, правила предметной области — в реестре `rules/`.

Перед выбором загрузчика агент получает паспорт вопроса командой
`python3 scripts/agent_harness.py context --task "..." --json`. Он фиксирует
опубликованное поколение, таблицы и запреты; этот пакет исполняет только
разрешённое чтение ledger и не заменяет маршрут новым разбором исходного Excel.

## Состав

| Модуль | Публичное | Зачем |
| --- | --- | --- |
| `schemas.py` | `LEDGER_TABLES`, `LedgerTableSchema`, `table_schema` | схема таблицы: обязательные колонки, колонки с датой, правила `R-*` |
| `loaders.py` | `load_table`, `summarize_table`, `load_work_orders`, `load_maintenance_plan_events`, `load_downtime_events`, `load_mtr_writeoffs`, `load_equipment_criticality`, `load_tech_card_operations`, `table_path`, `resolve_ledger_dir` | чтение таблицы с проверкой схемы и фильтрами; ограниченная по памяти сверка крупного носителя |

Тесты — `tests/test_data_loaders.py` (фикстурный мини-ledger в `tmp_path`).

## Как пользоваться

```python
from tof_reliability.data import load_work_orders, load_table

orders = load_work_orders(year=2025)                       # весь ТОРО за 2025
march = load_work_orders(period="2025-03", columns=["order_id", "equipment_id"])
plan = load_table("maintenance_plan_events", year=[2025, 2026])
```

Параметры общие у всех загрузчиков:

- `ledger_dir` — каталог ledger; по умолчанию из `config.resolve_data_parser_ledger_dir`
  (`TOF_DATA_PARSER_LEDGER_DIR`, см. `DATA_MAP.md`, слой 2);
- `columns` — какие колонки вернуть и в каком порядке; отсутствующая в файле
  необязательная колонка возвращается пустой, как это делали помощники
  `_read_csv(path, columns)` в аналитических модулях;
- `year` — год или список лет, `period` — `YYYY` либо `YYYY-MM` (тоже можно список);
- `missing_ok` — отсутствующий файл даёт пустую таблицу вместо ошибки.

`summarize_table(name, join_keys=...)` предназначен только для серверной
сквозной проверки: читает CSV порциями, возвращает число строк, покрытие и
пересечение точных ключей между таблицами, повторяющиеся устойчивые
идентификаторы и SHA-256 носителя. Он не возвращает
строки и не заменяет `load_table` в предметном расчёте.

## Инварианты

1. **Обязательные колонки — контракт, а не пожелание.** Их список объявлен в
   `schemas.py` и повторён в `docs/contracts/<таблица>.md`. Нет колонки —
   `LedgerSchemaError` с именем таблицы, путём файла и ссылкой на контракт;
   молча считать по отсутствующему полю нельзя (`R-CNT-004`, `R-OUT-001`).
2. **Единица периода — дата таблицы.** `year`/`period` считаются по первой
   непустой колонке из `schema.date_columns`, поэтому «2025 год» в разных
   таблицах означает одно и то же. У таблицы без дат (`equipment_registry`,
   `equipment_criticality_records`) фильтр по периоду — ошибка, а не пустой
   результат.
3. **Носитель выбирается сам.** Parquet берётся, только если он лежит рядом,
   не помечен устаревшим (`parquet_stale/` — туда `data_parser` переносит зеркала
   при инкрементальном рефреше) и в среде есть движок parquet. Иначе CSV. Новых
   зависимостей пакет не требует: без `pyarrow`/`fastparquet` всё читается из CSV.
4. **Все колонки — строки, пропуск — `""`.** Тот же контракт, что у прежних
   `pd.read_csv(dtype=str, keep_default_na=False)`: приведение типов и разбор
   дат — забота вызывающего расчёта.

## Границы

- Пакет не считает аналитику и не применяет правила счёта: схлопывание заказов
  в ремонтные эпизоды — `tof_reliability.rules`, а не здесь.
- Пакет не читает исходный Excel и не ходит в `data_parser`: единственный вход —
  готовый ledger (`R-PRC-002`).
- Срезы `views*` (`monthly_rebalance_input.csv`, `plan_match/`, `maintenance_program/`)
  под схемами не описаны: у них своя структура, они читаются модулями напрямую.

## Что ещё не переведено

Часть аналитических модулей читает ledger своими помощниками
`_read_csv(path, columns)`: они принимают уже готовый путь к файлу (иногда не из
каталога ledger) и молча возвращают пустую таблицу при ошибке чтения. Список
таких мест и причина, почему замена не механическая, — в `PROGRESS.md`.
